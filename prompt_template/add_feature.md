あなたは設計書作成の専門家です。

現在のシステムの設計書を基に、**AI利用文字認識機能設計書**を作成してください。

### 【目的】
- 新機能を安全かつ一貫性を持って追加できる、開発者向けの明確な設計書を作成する
- 既存アーキテクチャとの整合性を保ち、保守性を損なわない設計にする

### 【入力情報】
- 既存の設計書（または逆引き設計書）
- 追加したい新機能の仕様

### 【必須で含める内容】

**1. 新機能概要**
- 機能名称
- 目的・背景
- 期待される効果
- 優先度・緊急度

**2. 影響範囲分析**
- 影響する既存コンポーネント
- 変更が必要なファイル／モジュール
- 新規に作成すべきコンポーネント

**3. 詳細設計**

**3-1. 機能仕様**
- 入力（パラメータ、APIなど）
- 出力
- 処理フロー（Mermaidシーケンス図推奨）
- エッジケース・例外処理

**3-2. アーキテクチャ変更点**
- 新規追加クラス／モジュール
- 既存クラスへの変更内容
- インターフェース変更の有無

**3-3. データモデル変更**
- 新規追加／変更するモデル

**4. 実装タスク分解**
- 具体的な実装タスク一覧（チケット風）
- 推奨実装順序

**5. テスト計画**
- 追加すべきテストケース
- 既存テストへの影響

**6. リスクと考慮事項**
- 潜在的なリスク
- パフォーマンス・セキュリティへの影響
- 後方互換性

**7. リリース手順（簡易）**

### 【出力形式】
Markdownで章立てを明確に。図はMermaidを積極的に使用。

---

【既存設計書】
docs/system_design.md

【追加機能の仕様】
現在WinRtを用いた画像識別によってメンバー名とファン人数を取得している。
この時ユーザ名によって識別が正常に行われず手運用が発生している。
そのため、./modelsに格納されている。以下のモデルを利用し画像識別するように変更する
GGUF: models/llava-phi-3-mini-f16.gguf
mmproj: models/mmproj-gemma-4-E2B-it-BF16.gguf
また、プロンプトには以下を渡すこと
```
画像では以下のような表形式の画像が記載されている。
その中のユーザ名と総獲得ファン数だけを抽出すること。
|   |   |   |
|--|--|--|
|メンバー(固定文字列)|モルガン(ユーザ名)|アイコン|
|総獲得ファン数(固定文字列)|1,874,201,199(ユーザによって異なる)|人|

出力形式は以下の通りjson形式とする。
{
  ユーザ名: ファン数,
```
